**Opportunities**
- Add a small persistent `matter_registry` keyed by `matter_id` and `corpus_key` so rehydration is O(1) instead of a directory walk.
- Enforce one live in-process owner per `matter_id` with refcount/LRU semantics; never open a second `MatterModel` for the same matter in the same worker.
- Separate `logical_matter_id` from `corpus_key`. Use corpus fingerprint for reuse, but namespace it by tenant/workspace/client matter so service-layer state cannot alias accidentally.
- Make contradiction maintenance incremental: track dirty `issue_id`/`assertion_id`, scope existing-link preload to the current matter, and batch conflict gaps with `record_many()` instead of per-conflict transactions.
- Reuse the existing targeted recompute pattern for proof state instead of always ending runs with `compute_all()`.

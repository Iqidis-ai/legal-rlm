Because [src/irys/service/api.py#L1697](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/service/api.py#L1697) pages newest-first with `LIMIT/OFFSET`, and [src/irys/service/api.py#L1734](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/service/api.py#L1734) tells the client to request `offset + len(history)`, any new revision arriving between page N and page N+1 shifts all older rows down. The client can therefore miss one older row or re-read one from the previous page. The arithmetic is fine on a fixed snapshot; the drift is inherent to offset paging here.

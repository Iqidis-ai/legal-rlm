I found 2 HIGH issues and 1 MEDIUM issue in `ac8652b`.

**Findings**
1. HIGH: distinct documents collapse if they share a basename, so the second one can be hot-skipped incorrectly. [`engine.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/rlm/engine.py#L1250) passes `doc.filename` into inventory, but the reader defines `filename` as `path.name` rather than repository-relative path in [`reader.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/core/reader.py#L97). The inventory uniqueness key is `(matter_id, relative_path)` in [`schema.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/matter/schema.py#L160), and `is_ingested()` does an exact path lookup in [`graph.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/matter/graph.py#L875). Result: `contracts/msa.pdf` and `exhibits/msa.pdf` both become `msa.pdf`; once one is `complete`, the other can be skipped without analysis.

2. HIGH: changed content at the same path is never detected, so reused corpus keys can serve stale matter state. [`graph.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/matter/graph.py#L843) does `INSERT OR IGNORE`, then fetches by path/sha, but it never compares an existing row’s stored `sha256` to the incoming one or resets `ingest_status` on mismatch. The hot-path gate in [`engine.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/rlm/engine.py#L1256) only checks `is_ingested(relative_path)`. That makes the S3-prefix corpus key reuse in [`api.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/service/api.py#L338) more than a “v1 comment” issue: if `contract.pdf` changes in place under the same prefix, the old assertions are reused and the new bytes are skipped.

3. MEDIUM: concurrent runs on the same corpus can double-ingest the same pending document and duplicate occurrences. The `pending` behavior is good for crash recovery, but the skip check only blocks `complete` rows in [`engine.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/rlm/engine.py#L1256). `AssertionStore` always inserts an occurrence in [`graph.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/matter/graph.py#L92), and `assertion_occurrence` has no uniqueness constraint beyond the synthetic PK in [`schema.py`](C:/Users/devan/OneDrive/Desktop/Projects/legal-rlm/src/irys/matter/schema.py#L51). Two simultaneous runs can therefore record duplicate same-document occurrences.

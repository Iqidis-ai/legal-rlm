**Must fix**
- `get_cost_anomalies()` is not robust enough to catch the exact case this feature targets. It computes mean/σ on the same sample it is screening and then flags only `> mean + 2σ` (`src/irys/matter/matter.py:1506-1549`). With a low-N tier like `[1, 1, 100]`, the outlier inflates σ enough to hide itself. This is not tolerable to defer; early, sparse tiers are where this panel is most valuable.
- The “last 7 days / 24-hour bucket trend” is not actually trailing 7 days. The query groups by `SUBSTR(created_at, 1, 10)` and `LIMIT 7` active dates, with no date predicate and no zero-fill (`src/irys/matter/matter.py:1458-1468`). That returns up to seven days-with-calls, potentially spanning weeks. `estimated_monthly_burn_usd = last_week_cost * (30/7)` therefore scales arbitrary sparse history, not a true trailing-week burn (`src/irys/matter/matter.py:1479-1480`).

**Should fix**
- Yes, the exception-to-`zero` / `[]` fallback is failure laundering. Both methods turn operational failures into successful empty analytics (`src/irys/matter/matter.py:1491-1493,1570-1572`), and the UI suppresses breakdown/anomaly fetch errors again (`src/irys/ui/app.py:3131-3140`). That conflicts with the repo’s “surface missingness / no silent swallowing” direction (`.claude/CLAUDE.md:195,213`; `src/irys/matter/runtime.py:503-505,519-520`).
- The `Failures` card is computed from the sampled `calls` list, not matter-wide totals (`src/irys/ui/app.py:1230-1244,1246-1274`). If `breakdown` loads but `list_llm_calls` is empty, or if the matter has >250 calls, the panel can show `Failures = 0` while the detail text reports a nonzero matter-wide failure rate (`src/irys/ui/app.py:3130-3141`).
- Percentile indexing is slightly wrong. `_pct()` uses `int(len(vals) * q)` (`src/irys/matter/matter.py:1349-1353`), which overshoots by one when `q*N` is an integer; e.g. p95 at `N=20` returns the max instead of the 19th order statistic. Also, the docstring says stage/tier breakdowns have “the same metrics,” but those queries only return avg latency, not p50/p95/p99 (`src/irys/matter/matter.py:1291-1293,1378-1455`).

**Nice**
- The refresh path is chatty but probably acceptable short-term on local SQLite: `overview` + `list_llm_calls` + `get_cost_breakdown` + `get_cost_anomalies` are fetched serially (`src/irys/ui/app.py:3126-3141`), and the backend work includes 4 selects for breakdown plus per-tier anomaly selects (`src/irys/matter/matter.py:1327-1468,1506-1550`). Easy win: fold breakdown/anomalies into `stats()['llm']` or add one analytics endpoint.
